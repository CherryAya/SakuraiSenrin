# 词库审核

## 概览
本模块单独收纳 `wordbank` 的管理员审核相关能力，避免和普通用户常用的添加、搜索、删除、投票、恢复文档混在一起。这里专门说明待审核列表、通过、拒绝，以及回复审批通知 / 提交回执消息直接 `y` / `n` 的快捷审批流程。普通用户常用文档请查看 `#help 词库模块`。

## 权限与触发
- 触发方式: 指令触发 / 回复触发
- 权限: 群管理员

## 用法
- Help: `approval`

## 子功能目录
- `pending` 待审核词条: 查看当前可审核的待审词条。
- `approve` 通过审核: 通过指定待审词条。
- `reject` 拒绝审核: 拒绝指定待审词条。
- `approval-reply` 审批回复快捷方式: 回复审批通知或提交回执消息并 @ 机器人发送 `y` / `n`。

## 子功能详情
### `pending` 待审核词条
- 摘要: 查看当前群或全局可审核的待审词条。
- 别名: 待审, 待审核, review, wordbank.pending, 待审核词条
- 指令: `wordbank pending [关键词] [--page 页码] [--limit 每页数量]`
- 权限: 群管理员
#### 说明
> [!TIP]
> 当前群管理员或群主，只能查看当前群提交的待审核词条。
>
> 超级用户则可以直接查看全部待审核词条。

> [!TIP]
> 分页规则和 `wordbank search` 保持一致。
#### 常用示例命令
- `#wordbank pending`
- `#wordbank pending 晚安`
- `#wordbank pending event:poke --page 2 --limit 10`
#### 前置条件
需要当前群管理员/群主或超级用户权限。
#### 完整流程
```demo
USER: #wordbank pending 晚安
BOT: 待审核词条 (第 1 页):
#12 [current_group] 晚安 => 做个好梦  提交者: 10001
USER: #wordbank pending --page 2 --limit 10
BOT: 待审核词条 (第 2 页):
#26 [all_groups] 早 => 早安呀  提交者: 10002
```
#### 失败情况
无审核权限时返回权限提示；没有待审核词条时返回空结果说明。

### `approve` 通过审核
- 摘要: 通过指定待审核词条。
- 别名: pass, 通过, 审核通过, wordbank.approve, 通过词条, 审核通过词条
- 指令: `wordbank approve <id>`
- 权限: 群管理员
#### 说明
> [!TIP]
> 通过审核后，词条状态会改为 `approved`。
>
> 随后它会通过延迟重建加入运行时索引，并开始参与被动匹配。
#### 常用示例命令
- `#wordbank approve 12`
- `#通过词条 12`
- `#审核通过词条 12`
#### 前置条件
需要当前群管理员/群主或超级用户权限；群管理员只能审核当前群提交的词条。
#### 完整流程
```demo
USER: #wordbank approve 12
BOT: 词条 #12 已通过审核，稍后会参与被动匹配。
SYSTEM: 索引延迟重建完成后，普通消息就可以命中这条词条。
```
#### 失败情况
ID 非数字、词条不存在、词条不是待审核状态或当前用户没有审核权限时返回明确说明。

### `reject` 拒绝审核
- 摘要: 拒绝指定待审核词条。
- 别名: deny, 拒绝, 驳回, wordbank.reject, 拒绝词条, 驳回词条
- 指令: `wordbank reject <id>`
- 权限: 群管理员
#### 说明
> [!TIP]
> 拒绝后，词条状态会改为 `rejected`。
>
> 被拒绝的词条不会参与被动匹配。
#### 常用示例命令
- `#wordbank reject 13`
- `#拒绝词条 13`
- `#驳回词条 13`
#### 前置条件
需要当前群管理员/群主或超级用户权限；群管理员只能审核当前群提交的词条。
#### 完整流程
```demo
USER: #wordbank reject 13
BOT: 词条 #13 已拒绝，不会参与被动匹配。
SYSTEM: 被拒绝的词条不会进入运行时索引。
```
#### 失败情况
ID 非数字、词条不存在、词条不是待审核状态或当前用户没有审核权限时返回明确说明。

### `approval-reply` 审批回复快捷方式
- 摘要: 回复审批通知或提交回执消息，直接用 `y` / `n` 快捷审批。
- 别名: y, n, approve, reject, 通过, 拒绝
- 指令: 回复审批通知或提交回执并 @ 机器人发送 `y` / `approve` / `通过`，或 `n` / `reject` / `拒绝`
- 权限: 群管理员
#### 说明
> [!TIP]
> 新增词条进入 `pending` 后，系统会同时留下两类可回复消息：
>
> - 私聊超级用户的审批通知
> - 词条提交现场的提交回执

> [!TIP]
> 管理员回复这两类消息之一，并 `@` 机器人发送 `y` / `approve` / `通过`，就能一键通过。
>
> 发送 `n` / `reject` / `拒绝` 则是一键驳回。

> [!TIP]
> 这个快捷入口只对审批消息生效。
>
> 它不会影响普通词库自动回复里的 `详情 / 删除 / 恢复` 管理流程。
#### 常用示例命令
- `[回复审批通知] @机器人 y`
- `[回复审批通知] @机器人 n`
- `[回复提交回执] @机器人 approve`
- `[回复提交回执] @机器人 reject`
#### 前置条件
必须回复一条审批通知消息或提交回执消息；需要当前群管理员/群主或超级用户权限。
#### 完整流程
```demo
SYSTEM: 超级用户收到新增词条待审核通知。
USER: [回复审批通知] @机器人 y
BOT: 审批已完成：词条 #12 已通过。
USER: [回复提交回执消息] @机器人 n
BOT: 审批已完成：词条 #13 已拒绝。
SYSTEM: 审批源头会收到处理结果提示，便于提交者确认是否通过。
```
#### 失败情况
未回复审批通知、消息记录不存在、对应词条已被处理或当前用户没有审核权限时返回明确说明。
