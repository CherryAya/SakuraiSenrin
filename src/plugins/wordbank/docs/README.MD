# 词库模块

## 概览
添加、删除、管理词条，都在这里啦！

## 权限与触发
- 触发方式: 指令触发 / 被动触发
- 权限: 普通用户

## 用法
- Help: `wordbank`
- 常用入口: `#添加词条`、`#搜索词条`、`#删除词条`、`#苦瓜榜`

## 说明
> [!TIP]
> 最常用的是 `添加词条`、`搜索词条`、`删除词条` 和被动触发。

> [!TIP]
> 新增词条提交后会先进入 `pending`，审核通过前不会参与自动回复。

> [!TIP]
> 默认推荐 `触发词 => 响应词` 这种写法，最省事也最清楚。

## 子功能目录
### 主功能
- `add` 基础添加: 添加文本、图片或图文混排词条。
- `search` 搜索词条: 按关键词、图片或维度查询词条。
- `group` 展开 trigger group: 查看某个 trigger group 里的全部响应。
- `rank` 苦瓜榜: 查看已通过审核词条创建排行。
- `delete` 删除词条: 软删除自己创建或有权限处理的词条。
- `restore` 恢复词条: 恢复之前软删除的词条。
- `trigger` 修改触发词: 调整 trigger group 的触发条件。
- `response` 修改响应内容: 替换某条词条的回复内容。
- `passive` 被动触发: 普通消息或事件命中后自动回复。

### 高级功能
- `add-scope` 生效范围选项: 选择词条在哪些对象和场景上生效。
- `add-prob` 触发概率选项: 控制命中某个 trigger group 后是否真正回复。
- `add-weight` 权重选项: 控制同组多条响应之间的抽样倾向。
- `add-role` 触发角色选项: 限制只有指定角色身份命中时才触发。
- `add-call` 调用频率选项: 控制同一时间窗口内最多触发多少次。
- `reply-shortcut` 回复快捷操作: 回复凛凛词库消息后直接做详情、删除、恢复或快捷修改。

- `pending` 待审核词条: 查看当前可审核的待审词条。
- `approve` 通过审核: 通过指定待审词条。
- `reject` 拒绝审核: 拒绝指定待审词条。
- `approval-reply` 审批回复快捷方式: 回复审批通知或提交回执消息并 @ 凛凛发送 `y` / `n`。

## 子功能详情
### `add` 基础添加
- 摘要: 添加文本回复、图片回复、图片触发或图文混排词条。
- Hero: true
- Priority: 10
- 别名: 添加, 学习, wordbank.add, 添加词条
- 指令: `添加词条 触发词 => 响应词`
- 兼容指令: `wordbank add 触发词 => 响应词`、`wordbank.add 触发词 => 响应词`
- Demo: wordbank-add.webp
#### 说明
> [!TIP]
> 基础用法就是：`#添加词条 触发词 => 响应词`

> [!TIP]
> 不带参数直接发送 `#添加词条`，会进入一步一步的引导模式。

> [!TIP]
> 如果触发词或响应词里带空格，继续用 `=>` 分开就行。

> [!TIP]
> 也支持事件类触发词，比如 `[@]`、`[戳一戳]`、`[bot加群]`、`[新人加入]`。

> [!TIP]
> 响应词支持少量常用占位符：
>
> - `[账号]` -> 触发者账号
> - `[昵称]` -> 触发者昵称
> - `[群名片]` -> 触发者群名片，没有时回退为昵称
> - `[xx]` -> `昵称(群名片)[账号]`，并附带一张触发者头像

> [!TIP]
> 在引导模式的“请输入响应词”这一步，如果你回复的是一条合并转发，凛凛会继续问你：
>
> - `1` 作为一个整体响应导入
> - `2` 拆开成多条响应一次性导入

当前消息需要通过运行时检查。

### `add-scope` 生效范围选项
- 摘要: 选择词条在哪些对象和场景上生效。
- Advanced: true
- Priority: 110
- 别名: scope, 范围, 生效范围
- 指令: `添加词条 触发词 => 响应词 -s 本群|全局|自己|私聊`
- Demo: wordbank-add-scope.webp
#### 说明
> [!TIP]
> 常用中文写法：
>
> - `本群`
> - `全局`
> - `自己`
> - `私聊`

> [!TIP]
> 如果你走的是引导模式，系统本来就会单独询问范围。
>
> 这种情况下通常不需要再额外重复写 `--scope`。
#### 常用示例命令
- `#添加词条 大家好 => 大家好呀 -s 本群`
- `#添加词条 早上好 => 早安 -s 全局`
- `#添加词条 个人提醒 => 别忘记喝水 -s 自己`
- `#添加词条 私聊一下 => 收到 -s 私聊`
#### 前置条件
需要明确词条是群内通用、跨群、仅自己还是仅私聊。
#### 完整流程
```demo
USER: #添加词条 私聊一下 => 收到 -s 私聊
BOT: 词条已提交审核
ID: 16
状态: 待审核
触发词: 私聊一下
响应词: 收到
模式: contains
范围: 仅私聊
规则: 概率 1
权重: 3
管理员通过前不会触发。
SYSTEM: 这条词条只会在私聊里生效。
```
#### 失败情况
scope 拼写错误或重复设置时会返回说明。

### `add-prob` 触发概率选项
- 摘要: 控制命中某个 trigger group 后是否真正回复。
- Advanced: true
- Priority: 120
- 别名: prob, 概率, 触发概率
- 指令: `添加词条 触发词 => 响应词 --prob 0.0-1.0`
- Demo: wordbank-add-prob.webp
#### 说明
> [!TIP]
> 这个选项用来控制“命中了也不一定回”。
#### 常用示例命令
- `#添加词条 早 => 早安呀 -p 0.5`
- `#添加词条 哈哈 => 笑死 -p 0.2`
#### 前置条件
建议只用于容易高频误触的词条。
#### 完整流程
```demo
USER: #添加词条 早 => 早安呀 -p 0.5
BOT: 词条已提交审核
ID: 17
状态: 待审核
触发词: 早
响应词: 早安呀
模式: fullmatch
范围: 当前群
规则: 概率 0.5
权重: 3
管理员通过前不会触发。
SYSTEM: 这条词命中后，大约一半概率才会真正回复。
```
#### 失败情况
概率不是数字或不在 `0-1` 范围内时会提示。

### `add-weight` 权重选项
- 摘要: 控制同组多条响应之间的抽样倾向。
- Advanced: true
- Priority: 130
- 别名: weight, 权重
- 指令: `添加词条 触发词 => 响应词 --weight 1-5`
- Demo: wordbank-add-weight.webp
#### 说明
> [!TIP]
> 权重越高，这条回复越容易被抽中。
#### 常用示例命令
- `#添加词条 晚安 => 做个好梦 -w 5`
- `#添加词条 晚安 => 晚安晚安 -w 1`
#### 前置条件
适合同一触发词下存在多条候选响应的场景。
#### 完整流程
```demo
USER: #添加词条 晚安 => 做个好梦 -w 5
BOT: 词条已提交审核
ID: 18
状态: 待审核
触发词: 晚安
响应词: 做个好梦
模式: contains
范围: 当前群
规则: 概率 1
权重: 5
管理员通过前不会触发。
SYSTEM: 同一个触发词下，如果有多条回复，这条会更容易出现。
```
#### 失败情况
权重不是 `1-5` 的整数时会提示。

- Advanced: true
- Priority: 140
- 别名: role, roles, 角色限制
- 指令: `添加词条 触发词 => 响应词 -r 群主|管理|成员`
- Demo: wordbank-add-role.webp
#### 说明
> [!TIP]
> 这个选项用来限制“谁能触发这条词”。
#### 常用示例命令

- `#添加词条 群主确认 => 已收到 -r 群主`
- `#添加词条 萌新报道 => 欢迎加入 -r 成员`
#### 前置条件
只在群聊里有实际区分意义。
#### 完整流程
```demo
USER: #添加词条 管理员集合 => 管理员请看这里 -r 管理
BOT: 词条已提交审核
ID: 19
状态: 待审核
触发词: 管理员集合
响应词: 管理员请看这里
模式: contains
范围: 当前群
规则: 概率 1
权重: 3
管理员通过前不会触发。
SYSTEM: 这条词条只允许群管理员触发。
```
#### 失败情况
角色值非法时会提示。

### `add-call` 调用次数窗口选项
- 摘要: 按时间窗口限制触发次数区间。
- Advanced: true
- Priority: 150
- 别名: call, 调用次数窗口
- 指令: `添加词条 触发词 => 响应词 --call window:min:max`
- Demo: wordbank-add-call.webp
#### 说明
> [!TIP]
> 这个选项用来控制一段时间里第几次才回复。
#### 常用示例命令
- `#添加词条 连续打卡 => 你今天很活跃 --call 3600:3:10`
- `#添加词条 又来了 => 欢迎回来 --call 60:2:5`
#### 前置条件
适合限制高频触发词的回复节奏。
#### 完整流程
```demo
USER: #添加词条 又来了 => 欢迎回来 --call 60:2:5
BOT: 词条已提交审核
ID: 20
状态: 待审核
触发词: 又来了
响应词: 欢迎回来
模式: contains
范围: 当前群
规则: 概率 1
权重: 3
管理员通过前不会触发。
SYSTEM: 这条词在 60 秒里，第 2 次到第 5 次才会回复。
```
#### 失败情况
结构错误、数字非法、窗口超限或 `min > max` 时会提示。

### `search` 搜索词条
- 摘要: 统一搜索文本、图片或图文混排词条。
- Hero: true
- Priority: 20
- 别名: 查询, 搜索, wordbank.search, 搜索词条
- 指令: `搜索词条 [关键词] [图片] [--field all|trigger|response] [--creator 账号] [--page 页码] [--limit 每页数量]`
- 兼容指令: `wordbank search [关键词]`、`wordbank.search [关键词]`
- Demo: wordbank-search.webp
#### 说明
默认同时搜触发词和响应词，也支持按图片相似度搜索。结果会以卡片展示，可继续发送 `page <页码>`、`详情 <group_id>`、`del <组序号-响应序号...>` 或 `exit` 管理当前搜索会话。
#### 前置条件
无。
#### 完整流程
```demo
USER: #搜索词条 晚安
BOT: [词库搜索结果卡片]
BOT: 可发送 `page 页码`、`详情 组号`、`del 组序号-响应序号...` 或 `exit`
USER: 详情 271
BOT: [展开 trigger group 271]
```
#### 失败情况
没有命中、筛选参数非法或会话指令无效时会返回明确提示。

### `rank` 苦瓜榜
- 摘要: 查看全局已通过审核词条创建排行海报。
- Priority: 40
- 别名: 苦瓜榜, rank, 排行, 榜
- 指令: `苦瓜榜 [周榜|月榜|季榜|总榜]`
- 兼容指令: `wordbank rank [周榜|月榜|季榜|总榜]`
- Demo: wordbank-rank.webp
#### 说明
默认返回月榜，也支持周榜、季榜和总榜；海报展示 Top 10、冠军占比、覆盖群数等信息。
#### 常用示例命令
- `#苦瓜榜`
- `#苦瓜榜 周榜`
- `#wordbank rank 总榜`
#### 前置条件
无。
#### 完整流程
```demo
USER: #苦瓜榜
BOT: [发送苦瓜榜海报]
```
#### 失败情况
空榜时返回空榜结果；渲染失败会降级为文本榜单。

### `group` 组详情
- 摘要: 直接查看某个 trigger group 的完整详情。
- Advanced: true
- Priority: 160
- 别名: group, 展开
- 指令: `wordbank group <group_id> [--page 页码]`
- Demo: wordbank-search.webp
#### 说明
适合从搜索结果继续展开，查看 trigger、本组状态和各条响应详情；详情页内可继续翻页。
#### 常用示例命令
- `#wordbank group 271`
- `#wordbank group 271 --page 3`
#### 前置条件
需要知道 `group_id`。
#### 完整流程
```demo
USER: #wordbank group 271
BOT: Trigger Group #271
...
```
#### 失败情况
group 不存在、页码越界或参数非法时会提示。

### `delete` 删除词条
- 摘要: 软删除指定词条。
- Priority: 50
- 别名: 删除, remove, wordbank.delete, wordbank.del, 删除词条
- 指令: `删除词条 <id>`
- 兼容指令: `wordbank delete <id>`、`wordbank.delete <id>`、`wordbank.del <id>`
- Demo: wordbank-delete.webp
#### 说明
删除后不再参与匹配，但数据仍保留，可后续恢复。
#### 前置条件
需要提供数字词条 ID，且当前用户有对应操作权限。
#### 完整流程
```demo
USER: #删除词条 12
BOT: 词条 #12 已删除。
```
#### 失败情况
ID 非法、词条不存在或权限不足时会提示。

### `restore` 恢复词条

### `trigger` 修改触发词与触发概率
- 摘要: 修改 trigger group 的整体概率或触发内容。
- Advanced: true
- Priority: 70
- 别名: trigger, 触发, 触发词, trigger prob, trigger set
- 指令:
  - `wordbank trigger prob <group_id> <0.0-1.0>`
  - `wordbank trigger set <group_id> <新触发内容>`
- Demo: wordbank-trigger.webp
#### 说明
`trigger prob` 修改整组触发概率，不改动已有响应内容；`trigger set` 修改触发内容本身，支持纯文本、图片触发或图文混排。触发内容变更后，该组下已有响应会重新进入 `pending`，需要重新审核后才会重新参与被动匹配。
#### 常用示例命令
- `#wordbank trigger prob 271 0.3`
- `#wordbank trigger set 271 晚安啦`
- `#wordbank trigger set 271 [图片]`
#### 前置条件
`trigger prob` 与 `trigger set` 都要求当前用户对目标 trigger group 有修改权限；实际使用里通常由超级用户统一维护。
#### 完整流程
```demo
USER: #wordbank trigger prob 271 0.3
BOT: trigger group #271 的触发概率已更新为 0.3。
USER: #wordbank trigger set 271 晚安啦
BOT: trigger group #271 的触发词已更新，该组响应已重新进入待审核。
SYSTEM: `trigger prob` 只更新整组命中率；`trigger set` 修改触发内容后会让整组重新进入 pending，等待管理员重新审核。
```
#### 失败情况
group 不存在、触发词冲突、概率不在 `0-1` 范围内、图片无法识别或权限不足时会提示。

### `response` 修改响应词与响应权重
- 摘要: 修改某条响应内容或权重。
- Advanced: true
- Priority: 80
- 别名: response, 响应, 响应词, response weight, response set
- 指令:
  - `wordbank response weight <id> <1-5>`
  - `wordbank response set <id> <新响应内容>`
- Demo: wordbank-response.webp
#### 说明
`response weight` 只影响同一 trigger group 内多条响应的抽样权重；`response set` 用于改正文案、图片或图文混排响应。修改响应内容后，这一条响应会重新进入 `pending`，不会立刻生效。
#### 常用示例命令
- `#wordbank response weight 12 5`
- `#wordbank response set 12 做个好梦`
- `#wordbank response set 12 做个好梦 [图片]`
#### 前置条件
超级用户可修改任意响应；普通用户仅可改自己创建的响应。
#### 完整流程
```demo
USER: #wordbank response weight 12 5
BOT: 词条 #12 的响应权重已更新为 5。
USER: #wordbank response set 12 做个好梦
BOT: 词条 #12 的响应内容已更新，并重新进入待审核。
SYSTEM: `response weight` 只改变组内抽样倾向；`response set` 会改动响应内容本身，因此该条响应会重新进入 pending。
```
#### 失败情况
ID 非法、对象不存在、参数越界或权限不足时会提示。

### `passive` 被动匹配
- 摘要: 普通消息或事件命中词条后自动回复。
- Hero: true
- Priority: 30
- 别名: 被动, 自动回复
- 指令: 无
- Demo: wordbank-passive.webp
#### 说明
文本优先走内存索引，图片只在消息含图时下载并匹配。除普通文本外，也支持事件触发词，例如:
- `[@]`
- `[戳一戳]`
- `[bot加群]` / `[新人加入]`
- `[bot退群]` / `[成员退群]`

检测到撤回类信号或规则不通过时会直接跳过，不回复。
如果需要把这些事件词当普通文本录入，请在触发词前加 `\` 转义；响应词侧不会自动做事件解析。
#### 常用示例命令
- `#添加词条 [@] => 我在`
- `#添加词条 [戳一戳] => 别戳啦`
- `#添加词条 [新人加入] => 欢迎加入`
- `#添加词条 [bot加群] => 凛凛来啦`
- `#添加词条 \[戳一戳] => 这次是把它当普通文本`
#### 前置条件
词条已启用，且当前消息通过运行时检查。
#### 完整流程
```demo
USER: [戳一戳凛凛]
BOT: 别戳啦
SYSTEM: 如果命中的是 `group_recall` / `friend_recall` 一类撤回信号，词库会直接跳过，不发送回复。
```
#### 失败情况
未命中、规则不通过、概率未命中、图片失败或命中撤回信号时不回复。

### `reply-shortcut` 回复管理
- 摘要: 回复凛凛词库消息后，用短命令直接管理对应词条。
- Advanced: true
- Priority: 170
- 别名: info, 详情, history, 摘要, del, delete, 删除, rst, restore, 恢复, trigger prob, trigger set, response weight, response set
- 指令: 回复凛凛词库自动回复并发送 `info` / `history` / `del` / `rst` / `trigger prob` / `trigger set` / `response weight` / `response set`
- 兼容指令: `详情`、`history`、`删除`、`恢复`
- Demo: wordbank-reply-shortcut.webp
#### 说明
回复词库自动回复后，可以直接查看详情、摘要、删除、恢复，或做 `trigger` / `response` 快捷修改。搜索结果卡片和 group 详情页的上下文展开也复用这套记录。审批通知里的 `y / n` 不在这里，见 `#help wordbank pending`。
#### 前置条件
必须回复一条由词库系统记录过上下文的凛凛消息，且当前用户满足对应权限。
#### 完整流程
```demo
USER: [回复凛凛词库消息] @凛凛 info
BOT: 词条 #300 状态摘要
管理员审核通过后才变为 approved。
USER: [回复凛凛词库消息] @凛凛 详情
BOT: 词条详情 #12
触发: 晚安
响应: 做个好梦
USER: [回复凛凛词库消息] @凛凛 trigger prob 0.3
BOT: trigger group #12 的触发概率已更新为 0.3。
USER: [回复凛凛词库消息] @凛凛 response weight 5
BOT: 词条 #300 的响应权重已更新为 5。
SYSTEM: 回复快捷修改会自动从上下文里拿到对应的 trigger group 或 response item，不需要再次手填完整 ID。
```
#### 失败情况
未回复有效上下文、对象已清理、命令不受支持或权限不足时会提示。

- 摘要: 查看当前群或全局可审核的待审词条。

> [!TIP]

总数: 2
成功: 2
失败: 0
USER: #待审核词条 --page 2 --limit 10
BOT: [一条合并转发消息]

### `approval-reply` 审批回复快捷方式
- 摘要: 回复审批通知、提交回执或待审核合并转发首节点，直接做单条或批量审批。
- Advanced: true
- Priority: 940
- 别名: y, n, approve, reject, 通过, 拒绝
- 指令: 回复审批消息并 @ 凛凛发送 `y` / `approve` / `通过`，或 `n` / `reject` / `拒绝`；回复待审核首节点时也支持 `通过 1 2 5-8`、`拒绝 all`、`y 1 2 3`、`n 1 2 3`
- 权限: 群管理员
- Demo: wordbank-approval-approval-reply.webp
#### 说明
> [!TIP]
> 新增词条进入 `pending` 后，系统会同时留下两类可回复消息：
>
> - 私聊超级用户的审批通知
> - 词条提交现场的提交回执

> [!TIP]
> 管理员回复这两类消息之一，并 `@` 凛凛发送 `y` / `approve` / `通过`，就能一键通过。
>
> 发送 `n` / `reject` / `拒绝` 则是一键驳回。

> [!TIP]
> 回复 `待审核词条` 的合并转发首节点时，还可以按“序号”批量处理。
>
> 例如：`通过 1 3 5-8`、`拒绝 all`、`y 1 3 5-8`、`n 2 4`。

> [!TIP]
> `通过 / 拒绝` 只处理你点到的序号，其余不动。
>
> `y / n` 会把当前待审列表一次性处理完：
> `y 1 3` 表示通过 1、3，其余拒绝；`n 2 4` 表示拒绝 2、4，其余通过。

> [!TIP]
> 这个快捷入口只对审批消息生效。
>
> 它不会影响普通词库自动回复里的 `详情 / 删除 / 恢复` 管理流程。
#### 常用示例命令
- `[回复审批通知] @凛凛 y`
- `[回复审批通知] @凛凛 n`
- `[回复提交回执] @凛凛 approve`
- `[回复提交回执] @凛凛 reject`
- `[回复待审核首节点] @凛凛 通过 1 2 5-8`
- `[回复待审核首节点] @凛凛 拒绝 all`
- `[回复待审核首节点] @凛凛 y 1 3 5-8`
- `[回复待审核首节点] @凛凛 2 4 n`
#### 前置条件
必须回复一条审批通知消息或提交回执消息；需要当前群管理员/群主或超级用户权限。
#### 完整流程
```demo
SYSTEM: 超级用户收到新增词条待审核通知。
USER: [回复审批通知] @凛凛 y
BOT: 审批已完成：词条 #12 已通过。
USER: [回复提交回执消息] @凛凛 n
BOT: 审批已完成：词条 #13 已拒绝。
USER: [回复待审核首节点] @凛凛 通过 1 3-5
BOT: 批量通过完成
总数: 4
成功: 4
失败: 0
SYSTEM: 审批源头会收到处理结果提示，便于提交者确认是否通过。
```
#### 失败情况
未回复审批通知、消息记录不存在、对应词条已被处理或当前用户没有审核权限时返回明确说明。
