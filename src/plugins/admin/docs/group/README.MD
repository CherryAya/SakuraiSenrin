# 群组管理模块

## 概览
群组管理模块用于维护群状态，包括封禁、解封、授权、取消授权、退群、状态查询和批量群成员同步。所有动作都由超级管理员执行。

## 权限与触发
- 触发方式: 指令触发
- 权限: 超级管理员

## 用法
- Help: `admin.group`
- 命令入口: `#admin.group ...` / `#admin group ...` / `#群组管理 ...`

## 子功能目录
- `ban` 封禁群组: 把群标记为封禁状态。
- `unban` 解封群组: 解除封禁并恢复到封禁前状态。
- `auth` 授权群组: 允许凛凛在群内工作。
- `unauth` 取消授权: 把群改回未授权状态。
- `status` 查询状态: 查看当前群状态。
- `leave` 主动退群: 更新状态后尝试让凛凛退群。
- `sync-members-all` 全量同步群成员: 遍历当前所在全部群，分批同步成员缓存并通过管理员通知汇报进度。

## 子功能详情
### `ban` 封禁群组
- 摘要: 把群标记为封禁状态。
- 别名: 封禁, 拉黑
- 指令: `#admin.group ban <gid>`
- Demo: admin-group-ban.webp
#### 说明
> [!TIP]
> `ban` 会把群状态改为 `BANNED`。
>
> 后续运行时检查会直接拦住这个群，不再继续正常使用凛凛。
#### 前置条件
目标群必须已在数据库中存在，且执行者拥有超级管理员权限。
#### 完整流程
传入一个或多个群号即可批量处理。
```demo
USER: #admin.group ban 114514
BOT: [114514|测试群] 已封禁
```
#### 失败情况
非法群号会直接报错；数据库中不存在该群记录时，会提示该群还未入库。

### `unban` 解封群组
- 摘要: 解除封禁并恢复到封禁前状态。
- 别名: 解封, 加白
- 指令: `#admin.group unban <gid>`
- Demo: admin-group-unban.webp
#### 说明
> [!TIP]
> `unban` 会优先恢复到该群被封禁前的状态。
>
> 若是历史旧数据、缺少封禁前状态记录，则会回退到安全默认值，并在返回文案中明确说明。
>
> 对普通群管理层而言，如果不是走超管手动解封，也可以在“黑名单邀请自动拒绝”的私聊提示中直接使用 `#自助解封` 进入受限的自助流程。
#### 前置条件
目标群当前应处于封禁状态。
#### 完整流程
先解封；如果封禁前就是已授权或休眠状态，解封后会直接恢复过去状态。
```demo
USER: #admin.group unban 114514
BOT: [114514|测试群] 已解封，状态恢复为已授权
```
#### 失败情况
如果群本来就没被封禁，会提示“未被封禁，无需解封”。

### `auth` 授权群组
- 摘要: 允许凛凛在群内工作。
- 别名: 授权
- 指令: `#admin.group auth <gid>`
- Demo: admin-group-auth.webp
#### 说明
> [!TIP]
> `auth` 会把群状态改为 `AUTHORIZED`。
>
> 从这一刻起，运行时检查链才会允许该群继续正常使用凛凛。
#### 前置条件
目标群不能处于封禁状态。
#### 完整流程
对新入库但未授权的群执行即可。
```demo
USER: #admin.group auth 114514
BOT: [114514|测试群] 授权成功
```
#### 失败情况
如果群已授权，会提示无需重复操作；若群被封禁，会要求先解封。

### `unauth` 取消授权
- 摘要: 把群改回未授权状态。
- 别名: 取消授权
- 指令: `#admin.group unauth <gid>`
- Demo: admin-group-unauth.webp
#### 说明
> [!TIP]
> `unauth` 用于暂停凛凛在某个群工作。
>
> 它不会把群加入封禁名单，只是把状态改回未授权。
#### 前置条件
目标群当前最好处于授权状态。
#### 完整流程
执行后群会回到未授权状态。
```demo
USER: #admin.group unauth 114514
BOT: [114514|测试群] 已取消授权
```
#### 失败情况
如果群已是未授权状态，会提示无需操作；如果群被封禁，则不会进行取消授权。

### `status` 查询状态
- 摘要: 查看当前群状态。
- 别名: 状态
- 指令: `#admin.group status <gid>`
- Demo: admin-group-status.webp
#### 说明
> [!TIP]
> `status` 是纯查询动作。
>
> 它只读，不会修改数据库里的群状态。
#### 前置条件
目标群应存在于数据库中。
#### 完整流程
输入群号即可查看状态。
```demo
USER: #admin.group status 114514
BOT: [114514|测试群] 当前状态: 已授权
```
#### 失败情况
如果群记录不存在，会提示数据库中不存在该群组记录。

### `leave` 主动退群
- 摘要: 更新状态后尝试让凛凛退群。
- 别名: 退群
- 指令: `#admin.group leave <gid>`
- Demo: admin-group-leave.webp
#### 说明
> [!TIP]
> `leave` 会先把群状态写成 `LEFT`，再调用 OneBot API 退群。
>
> 所以即使退群接口失败，数据库状态也可能已经先被更新。
#### 前置条件
凛凛当前仍在该群内。
#### 完整流程
执行后会同步更新数据库状态。
```demo
USER: #admin.group leave 114514
BOT: [114514|测试群] 已退群
```
#### 失败情况
如果退群 API 调用失败，文案会明确说明“退群失败，仅更新数据库状态”。

### `sync-members-all` 全量同步群成员
- 摘要: 遍历当前所在全部群，分批同步群成员缓存并通过管理员通知汇报进度。
- 别名: 无
- 指令: `#admin.group sync-members-all` / `#admin group sync-members-all`
#### 说明
> [!TIP]
> 该命令会通过 `get_group_list()` 获取凛凛当前仍在的所有群，然后逐群调用成员列表同步。
>
> 每个群之间固定间隔 `6s`，每完成 `10` 个群会按管理员通知配置发送一次合并转发进度报告，任务结束后再发送最终汇总。
#### 前置条件
执行者必须拥有超级管理员权限，且当前没有其他 `sync-members-all` 任务在运行。
#### 完整流程
命令入口只做启动与结果提示，详细进度通过管理员通知上报。
```demo
USER: #admin group sync-members-all
BOT: 已开始执行群成员全量同步，后续进度会通过管理员通知汇报。
```
#### 失败情况
若已有同类任务在运行，会直接返回当前任务摘要；单个群同步失败不会中断整体任务，失败原因会写入进度与最终汇总。
