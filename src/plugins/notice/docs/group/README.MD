# 群组事件处理

## 概览
群组事件处理模块负责清理高风险群事件，包括被踢、被禁言后的自动退群与拉黑联动；同时也承担入群同步和群名变更同步。

## 权限与触发
- 触发方式: 被动触发
- 权限: 超级管理员

## 用法
- Help: `notice.group`

## 子功能目录
- `kick-cleanup` 被踢清理: 凛凛被踢后更新群状态并通知超管。
- `ban-cleanup` 被禁言清理: 凛凛被禁言后自动退群并拉黑操作者。
- `member-sync` 入群同步: 凛凛入群后同步群成员缓存。
- `rename-sync` 群名同步: 监听群名变更并更新缓存。

## 子功能详情
### `kick-cleanup` 被踢清理
- 摘要: 凛凛被踢后更新群状态并通知超管。
- 别名: 被踢, kick
- 指令: 被动触发
- Demo: notice-group-kick-cleanup.webp
#### 说明
> [!TIP]
> 当凛凛被管理员踢出群聊时，模块会自动更新群状态。
>
> 处理完成后，还会把事件摘要上报给超管，便于后续排查。
#### 前置条件
收到 `GroupDecreaseNoticeEvent` 且事件代表凛凛自己被移除。
#### 完整流程
状态更新和通知都自动完成。
```demo
SYSTEM: 凛凛被踢出群 114514。
BOT: [私聊超管] 群组被踢出
不好，被扔出来了，已自动拉黑...
```
#### 失败情况
如果通知发送失败，只会影响告警，不会阻止状态清理。

### `ban-cleanup` 被禁言清理
- 摘要: 凛凛被禁言后自动退群并拉黑操作者。
- 别名: 禁言清理, ban
- 指令: 被动触发
- Demo: notice-group-ban-cleanup.webp
#### 说明
> [!TIP]
> 当凛凛在群内被禁言时，模块会走强制清理路径。
>
> 它会把群设为封禁状态、拉黑操作者，并自动退出相关群。
#### 前置条件
收到 `GroupBanNoticeEvent`，且事件目标是凛凛。
#### 完整流程
先更新群状态，再通知超管。
```demo
SYSTEM: 群 114514 对凛凛执行了禁言。
BOT: [私聊超管] 群组禁言
检测到禁言行为，已自动退出群聊...
```
#### 失败情况
若某些连坐退群动作失败，会在通知里带上失败记录。

### `member-sync` 入群同步
- 摘要: 凛凛入群后同步群成员缓存。
- 别名: 入群同步
- 指令: 被动触发
- Demo: notice-group-member-sync.webp
#### 说明
> [!TIP]
> 凛凛成功入群后，会立即触发一次群成员同步。
>
> 这样做是为了避免刚入群时缓存缺失，影响后续运行时判断。
#### 前置条件
收到 `GroupIncreaseNoticeEvent` 且是凛凛入群。
#### 完整流程
整个同步过程对用户无感知。
```demo
SYSTEM: 凛凛加入新群 114514。
自动执行群成员同步。
```
#### 失败情况
如果同步失败，应通过日志排查，不会主动给普通群成员提示。

### `rename-sync` 群名同步
- 摘要: 监听群名变更并更新缓存。
- 别名: 改名同步
- 指令: 被动触发
- Demo: notice-group-rename-sync.webp
#### 说明
> [!TIP]
> 当群名变化时，模块会同步更新群缓存。
>
> 后续日志和文案就会优先使用新的群名。
#### 前置条件
收到 `NotifyEvent`，且 `sub_type` 为 `group_name`。
#### 完整流程
自动更新缓存，不向用户输出文案。
```demo
SYSTEM: 群名从“旧群名”改为“新群名”。
已同步群缓存名称。
```
#### 失败情况
若缓存更新失败，只能通过日志排查，当前不会主动回退。
