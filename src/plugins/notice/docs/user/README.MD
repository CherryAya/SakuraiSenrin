# 用户事件处理

## 概览
用户事件处理模块目前只负责好友请求这一件事：自动同意申请、补充用户记录，并通知管理员。它是一个单功能被动插件，不需要再拆子功能目录。

## 权限与触发
- 触发方式: 被动触发
- 权限: 超级管理员

## 用法
- Help: `notice.user`
- 别名: 好友申请
- 指令: 被动触发
- Demo: notice-user-main.webp
## 说明
> [!TIP]
> 模块收到好友请求后，不会立刻秒同意。
>
> 它会先随机延迟一小段时间，尽量避免行为模式过于机械。

> [!TIP]
> 请求同意后，还会顺手补充用户库记录，并通过管理员通知上报。
>
> 有效好友请求仍自动同意，不按用户黑名单筛选。用户 ID 非法、请求 flag 为空或全为空白时，只记录诊断，不等待、不调用审批接口，也不发送“已同意”通知。正常 flag 按收到的原样使用。
## 前置条件
收到用户 ID 有效、带非空白 flag 的 `FriendRequestEvent`，且 Bot 可以正常调用添加好友接口。
## 完整流程
同意好友请求后再通过管理员通知汇报。
```demo
SYSTEM: 收到来自 12345 的好友请求。
BOT: 自动同意好友请求。
BOT: [管理员通知] 收到了新的好友请求，已同意：12345
```
## 失败情况
- 同意接口被平台拒绝或遇到网络故障时，不记录为成功，也不发送“已同意”通知；改为通知管理员检查好友状态，必要时让对方重新申请。
- 同意已经成功后，获取昵称失败、网络故障或返回无效资料不撤销同意；继续补充用户记录并通知管理员。
- 发送管理员通知失败会由现有异常链路记录，当前不自动重试。
