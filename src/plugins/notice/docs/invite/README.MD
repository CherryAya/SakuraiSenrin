# 群组邀请处理

## 概览
请求 flag 不能为空或全为空白；非法请求不会调用平台审批，也不会创建待办。合法 flag 原样使用。机器人已经入群后收到的无 flag 入群通知不受这条请求校验影响，仍按群状态处理授权或退群。

群组邀请处理模块负责记录明确邀请机器人本人的群邀请，以及机器人入群后需要授权的待办，并根据群当前状态做自动处理或上报超级管理员。

模块不会代办其他成员的入群申请。邀请对象缺失、无效或并非机器人本人时，不执行审批，并在运行日志中留下诊断信息。

### 通知中的群名和邀请者

- 群名优先使用本次事件附带的 `group_name`，其次复用确认入群状态时已取得的群列表名称，再降级到本地缓存/数据库，最后显示群号。
- 邀请者昵称优先使用请求事件附带的 `nickname` / `inviter_name` 或身份匹配的 `sender.nickname`；入群通知只使用操作人名称，避免将机器人本人的昵称当作邀请者。缺失时降级到本地资料，最后显示 QQ 号。
- 上游有名称扩展字段时会优先使用，但 OB11 标准不保证这些字段存在。名称解析不额外调用 `get_group_info` 或 `get_stranger_info`。
- 已取得的有效名称通过现有 repository 更新缓存并按现有写入策略保存，空白或非法名称不会覆盖旧资料。通知显示“昵称（QQ 号）”；只有 QQ 号时不会重复显示。
- 请求和入群通知合并后保留原邀请者身份，不会将后续操作人的昵称挂到原邀请者 QQ 号上。平台名称按纯文本显示，不执行其中的 CQ 码。

## 权限与触发
- 触发方式: 被动触发
- 权限: 超级管理员

## 用法
- Help: `notice.invite`

## 子功能目录
- `auto-approve-authorized` 已授权群自动放行: 机器人尚未入群时，自动同意已授权群发给机器人本人的有效邀请。
- `auto-reject-banned` 封禁群自动拒绝: 黑名单群的邀请自动拒绝并通知相关人。
- `report-pending` 普通邀请上报: 邀请与机器人入群通知合并为同一待办，供管理员审批或授权。

## 子功能详情
### `auto-approve-authorized` 已授权群自动放行
- 摘要: 机器人尚未入群时，自动同意已授权群发给机器人本人的有效邀请。
- 别名: 自动放行
- 指令: 被动触发
- Demo: notice-invite-auto-approve-authorized.webp
#### 说明
> [!TIP]
> 如果群已经获得授权，且平台明确邀请机器人本人，机器人尚未在群时会自动同意该邀请。
>
> 机器人已经在群时，不再调用入群审批，也不会因此替其他成员同意入群。
#### 前置条件
群记录存在，且状态为 `AUTHORIZED` 或 `DORMANT`；邀请对象明确为机器人本人，且能够确认机器人尚未入群。
#### 完整流程
确认邀请对象及机器人当前入群状态后，自动同意有效邀请。
```demo
SYSTEM: 已授权群 114514 邀请尚未在群内的机器人本人。
自动同意入群，无需人工审批。
```
#### 失败情况
如果暂时无法确认机器人是否已在群，或平台处理失败，不报告成功，管理员可稍后重试并查看运行日志。

平台拒绝或网络故障后会重新确认机器人是否已经入群；只有确认已在群，才完成本地处理。封禁群的拒绝接口失败后若确认机器人已经入群，会改为退群；退群接口失败后只有确认机器人确实已离群，才记录拒绝完成。

### `auto-reject-banned` 封禁群自动拒绝
- 摘要: 黑名单群的邀请自动拒绝并通知相关人。
- 别名: 自动拒绝, 黑名单邀请
- 指令: 被动触发
- Demo: notice-invite-auto-reject-banned.webp
#### 说明
> [!TIP]
> 如果群已被标记为封禁状态，模块会自动拒绝发给机器人本人的有效邀请；机器人已在群时则退出该群。
>
> 同时还会把结果分别通知邀请者和超级管理员。
>
> 给邀请者的私聊提示里会直接带出 `#自助解封` / `#self.unban` 引导，方便仍是该群管理层的人按流程发起群聊自助解封。
>
> 这里给出的只是“入口提示”，真正能否解封，仍以后续自助解封流程里的管理身份、用户额度、群额度和理由校验为准。
#### 前置条件
群记录存在，且状态为 `BANNED`；事件为明确邀请机器人本人的请求，或机器人本人的入群通知。
#### 完整流程
完成拒绝或退群后，对邀请者和超管分别发送通知。
```demo
SYSTEM: 封禁群 114514 发来邀请。
BOT: [私聊邀请者] 群聊已被拉黑，凛凛不想加入此群组。若你仍是该群管理层，可发送 #自助解封 按提示发起自助解封。
BOT: [管理员通知] 黑名单群组发起邀请，已自动拒绝。
```
#### 失败情况
如果私聊发送失败，不会阻止拒绝动作本身。

#### 补充说明
- 这条提示不会自动帮邀请者发起解封，只是把入口说清楚。
- 如果邀请者已经不再是该群管理层，后续进入 `#自助解封` 后也不会在候选列表里看到这个群。
- 如果该邀请者或该群的自助额度已用尽，后续流程会明确提示联系超管。

### `report-pending` 普通邀请上报
- 摘要: 邀请与机器人入群通知合并为同一待办，供管理员审批或授权。
- 别名: 邀请上报
- 指令: 被动触发
- Demo: notice-invite-report-pending.webp
#### 说明
> [!TIP]
> 对于既未授权也未封禁的普通群，模块会记录邀请并上报管理员。
>
> 发给机器人本人的邀请请求和机器人入群通知共用同一条待办，不论两者先后顺序如何，同一次邀请不会因此上报两份待办。重复送达的同一邀请也不会重复上报。
>
> 原通知的回复入口会保留。机器人尚未入群时，处理平台邀请；已入群时，处理本地群授权或退群。

> [!TIP]
> 上报链路支持多路通知：
>
> - 管理员私聊
> - 通知群
>
> 可通过 `ADMIN_NOTIFY_PRIVATE_ENABLED`、`ADMIN_NOTIFY_GROUP_ENABLED`、`ADMIN_NOTIFY_GROUP_IDS` 控制是否开启及投递目标。

> [!TIP]
> 通知消息里会同时附带两类处理方式：
>
> - 回复 `y` / `n`：尚未入群时同意 / 拒绝；已入群时授权 / 退群
> - 主动命令 `#admin.invite approve -g <gid>` / `#admin.invite reject -g <gid>`
#### 前置条件
邀请请求必须明确邀请机器人本人，并能解析群号、邀请者和有效的邀请标识；入群通知必须是机器人本人的入群事件。
#### 完整流程
记录或合并待办，再通知邀请者和管理员。收到的是入群通知时，管理员通知会明确写出“已入群，等待群授权”。
```demo
SYSTEM: 新群 114514 发来邀请。
BOT: [私聊邀请者] 谢谢您对凛凛发起的邀请 ^_^
BOT: [管理员通知] 📩 机器人入群邀请待处理
```
#### 失败情况
如果邀请消息发送失败，对应 message_id 记录也不会建立，之后无法使用回复快捷审批。

管理员操作时会重新确认机器人是否在群。无法确认时请稍后重试；机器人尚未入群且邀请已经失效，或旧记录不能确认邀请对象时，需要重新邀请机器人。
