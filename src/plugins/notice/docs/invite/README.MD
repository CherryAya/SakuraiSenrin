# 群组邀请处理

## 概览
群组邀请处理模块负责记录每一次群邀请，并根据群当前状态做自动同意、自动拒绝或上报超级管理员处理。

## 权限与触发
- 触发方式: 被动触发
- 权限: 超级管理员

## 用法
- Help: `notice.invite`

## 子功能目录
- `auto-approve-authorized` 已授权群自动放行: 已授权群的邀请直接放过，不再重复打断。
- `auto-reject-banned` 封禁群自动拒绝: 黑名单群的邀请自动拒绝并通知相关人。
- `report-pending` 普通邀请上报: 普通邀请写入记录并通知管理员审批。

## 子功能详情
### `auto-approve-authorized` 已授权群自动放行
- 摘要: 已授权群的邀请直接放过，不再重复打断。
- 别名: 自动放行
- 指令: 被动触发
- Demo: notice-invite-auto-approve-authorized.webp
#### 说明
> [!TIP]
> 如果被邀请的群已经在数据库里处于工作状态，就不会再重复打断管理员审批。
>
> 这条路径的目标是减少重复邀请带来的噪音。
#### 前置条件
群记录存在，且状态为 `AUTHORIZED` 或 `DORMANT`。
#### 完整流程
事件进入后直接结束处理。
```demo
SYSTEM: 已授权群 114514 再次发来邀请。
自动跳过人工审批，不再额外推送消息。
```
#### 失败情况
如果群状态判断错误，可能会产生重复邀请记录，需要通过仓库日志排查。

### `auto-reject-banned` 封禁群自动拒绝
- 摘要: 黑名单群的邀请自动拒绝并通知相关人。
- 别名: 自动拒绝, 黑名单邀请
- 指令: 被动触发
- Demo: notice-invite-auto-reject-banned.webp
#### 说明
> [!TIP]
> 如果群已被标记为封禁状态，模块会自动拒绝邀请。
>
> 同时还会把结果分别通知邀请者和超级管理员。
>
> 给邀请者的私聊提示里会直接带出 `#自助解封` / `#self.unban` 引导，方便仍是该群管理层的人按流程发起群聊自助解封。
>
> 这里给出的只是“入口提示”，真正能否解封，仍以后续自助解封流程里的管理身份、用户额度、群额度和理由校验为准。
#### 前置条件
群记录存在，且状态为 `BANNED`。
#### 完整流程
对邀请者和超管分别发送通知。
```demo
SYSTEM: 封禁群 114514 发来邀请。
BOT: [私聊邀请者] 群聊已被拉黑，凛凛不想加入此群组。若你仍是该群管理层，可发送 #自助解封 按提示发起自助解封。
BOT: [管理员通知] 黑名单群组发起邀请，已自动拒绝。
```
#### 失败情况
如果私聊发送失败，不会阻止拒绝动作本身。

#### 补充说明
- 这条提示不会自动帮邀请者发起解封，只是把入口说清楚。
- 如果邀请者已经不再是该群管理层，后续进入 `#自助解封` 后也不会在候选列表里看到这个群。
- 如果该邀请者或该群的自助额度已用尽，后续流程会明确提示联系超管。

### `report-pending` 普通邀请上报
- 摘要: 普通邀请写入记录并通知管理员审批。
- 别名: 邀请上报
- 指令: 被动触发
- Demo: notice-invite-report-pending.webp
#### 说明
> [!TIP]
> 对于既未授权也未封禁的普通群，模块会把邀请记录下来并上报管理员通知。
>
> 这才是需要人工审批的常规路径。

> [!TIP]
> 上报链路支持多路通知：
>
> - 管理员私聊
> - 通知群
>
> 可通过 `ADMIN_NOTIFY_PRIVATE_ENABLED`、`ADMIN_NOTIFY_GROUP_ENABLED`、`ADMIN_NOTIFY_GROUP_IDS` 控制是否开启及投递目标。

> [!TIP]
> 通知消息里会同时附带两类处理方式：
>
> - 回复 `y` / `n`
> - 主动命令 `#admin.invite approve -g <gid>` / `#admin.invite reject -g <gid>`
#### 前置条件
需要能够解析出群号、邀请者以及可选 flag。
#### 完整流程
先写邀请记录，再给邀请者和管理员通知发消息。
```demo
SYSTEM: 新群 114514 发来邀请。
BOT: [私聊邀请者] 谢谢您对凛凛发起的邀请 ^_^
BOT: [管理员通知] 📩 新的邀请事件通知
```
#### 失败情况
如果邀请消息发送失败，对应 message_id 记录也不会建立，之后无法使用回复快捷审批。
