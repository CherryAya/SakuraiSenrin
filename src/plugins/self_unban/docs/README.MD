# 自助解封

## 概览
给被拉黑的用户和被封禁的群聊一个受控的自助恢复入口。入口统一为 `#自助解封` / `#self.unban`，采用交互式选择，不再要求用户记忆子命令。

额度规则：
- 每个用户生命周期内最多成功自助解封 `2` 次。
- 每个群生命周期内最多成功自助解封 `2` 次。
- 群聊解封成功时，会同时消耗“发起人 1 次额度”和“目标群 1 次额度”。
- 第 `3` 次及以上一律不允许继续自助解封，要求联系超管。

## 权限与触发
- 触发方式: 指令触发
- 权限: 普通用户 / 群管理员

## 快捷入口
- 直接指令: `#自助解封` / `#self.unban`
- 邀请拒绝提示入口: 如果某个封禁群再次邀请凛凛，邀请者会在私聊提示里直接看到这两个命令
- 使用建议: 优先直接发送 `#自助解封`，由凛凛拉出当前可处理对象列表，而不是手动猜测自己还能解封哪个群

## 子功能目录
- `self` 解封自己: 解除自己的全局黑名单；若在当前群里被做了群级个人拉黑，也支持解除当前群作用域。
- `group` 解封群聊: 解除你仍是管理层、且当前处于封禁状态的群聊。

## 子功能详情
### `self` 解封自己
- 摘要: 解除自己的黑名单，需要填写不少于 10 个字的理由。
- 指令: `#自助解封`
- 别名: `#self.unban`
#### 说明
如果你本人存在可解封目标，凛凛会在交互里提供“解封自己”选项。成功后只消耗你自己的额度，不影响任何群的额度。

即使当前只有“解封自己”一个可选项，流程也仍然会先展示对象类型列表，再由你确认进入理由填写阶段。
#### 前置条件
你本人当前确实仍在可处理的黑名单中，且你的历史成功自助解封次数少于 2 次。
#### 完整流程
```demo
USER: #自助解封
BOT: 请选择要解封的对象类型：
1. 解封自己
2. 解封群聊
USER: 1
BOT: 请输入本次全局自助解封理由（至少 10 个字）。本次通过后会消耗 1 次额度，当前剩余 2 次。
USER: 之前连续刷屏已经停止，后续会遵守群规正常交流
BOT: 已解除全局黑名单。已使用 1/2 次自助解封，剩余 1 次。
```
#### 失败情况
理由为空、全空白或少于 10 个字时会要求重填；如果当前并未处于可解封黑名单中，或你个人额度已用尽，会直接拒绝并提示联系超管。

### `group` 解封群聊
- 摘要: 解除你管理的封禁群聊，成功后恢复到封禁前状态。
- 指令: `#自助解封`
- 别名: `#self.unban`
#### 说明
凛凛会拉取“你仍是管理层、当前确实被封禁、且你与该群都还有剩余额度”的群聊列表，按“群名 + 群号”展示，供你选择。成功后同时扣减你的 1 次额度和目标群的 1 次额度。

新产生的封禁会恢复到真实的封禁前状态；若是历史旧数据、缺少封禁前状态记录，则会明确提示本次使用了安全回退值。

如果你是从“黑名单群邀请自动拒绝”的私聊提示里进入，通常看到的就是这条群聊解封路径。只要你仍是该群管理层，且你和该群都还有剩余额度，这个群就会出现在候选列表中。
#### 前置条件
发起人当前仍是目标群管理层；目标群状态为 `BANNED`；发起人和目标群的历史成功自助解封次数都少于 2 次。
#### 完整流程
```demo
USER: #自助解封
BOT: 请选择要解封的对象类型：
1. 解封自己（当前不可用）
2. 解封群聊
USER: 2
BOT: 请选择要解封的群聊，回复序号、群号或群名：
1. 测试群（20001）- 你的剩余额度 2 次 / 本群剩余额度 1 次
2. 备用群（20002）- 你的剩余额度 2 次 / 本群剩余额度 2 次
USER: 1
BOT: 请输入群 测试群（20001）的自助解封理由（至少 10 个字）。本次通过后会同时消耗你 1 次额度和本群 1 次额度。你当前剩余 2 次，本群剩余 1 次。
USER: 原先的风控问题已经处理完成，后续不会再出现禁言机器人行为
BOT: 已解除群 测试群（20001）封禁，当前状态恢复为已授权。你的额度已用 1/2 次，剩余 1 次；本群额度已用 2/2 次，剩余 0 次。
```
#### 失败情况
非管理层不会出现在可选群列表里；未封禁群、群额度已用尽、发起人额度已用尽、以及缺少合规理由的申请都会被拒绝。

## 邀请拒绝联动
当一个已封禁群再次邀请凛凛时，`notice.invite` 会：
1. 自动拒绝邀请或在入群通知场景下主动退群。
2. 私聊邀请者，说明该群当前已被拉黑。
3. 在私聊文案里直接附上 `#自助解封` / `#self.unban` 引导。

这条联动只负责“告诉你如何进入自助解封流程”，不会绕过任何额度、身份和理由校验。

## Case-措施矩阵
| Case | 措施 |
| --- | --- |
| 黑名单对象被运行时拦截，命令进不来 | 插件声明 `no_check=True`，绕过黑名单和群封禁拦截链，只放开自助解封入口 |
| 用户忘记参数，命令过长或记不住子命令 | 改为 `#自助解封` 统一入口，按步骤引导选择自己或群聊 |
| 用户为群解封后，自己次数没扣掉 | 群解封成功时写两条额度记录，同时扣减“用户额度 + 群额度” |
| 同一用户跨多个群反复解封 | 用户额度按生命周期全局累计，第二次成功后即不能再为任何群发起第三次解封 |
| 群解封后错误回到 `UNAUTHORIZED` | 新封禁链路持久化 `pre_ban_status`，解封时恢复真实前态 |
| 旧数据里群已封禁，但没有历史前态 | 明确走安全回退值，并在结果和超管通知里说明不是精确恢复 |
| 多个管理员同时为同一群发起自助解封 | 服务层同时锁住“发起人额度”和“群额度”，锁内二次计数，防止并发双扣 |
| 群在列表展示后已被别人解封 | 提交阶段重新校验群状态；若已不再封禁，直接返回无需解封 |
| 选择了无效序号 / 群号 / 群名 | 明确拒绝并要求重新选择，不进入理由环节 |
| 理由过短、纯空白或敷衍 | 归一化后校验最少 10 字，不达标则原地重填 |
| 管理层身份变化，用户已不再是管理员 | 群列表只基于当前成员权限查询，失去管理身份后不会再出现在可选项中 |
