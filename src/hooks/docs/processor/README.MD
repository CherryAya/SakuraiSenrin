# 检测服务

## 概览
检测服务 hook 是项目运行时的第一道统一检查链，负责缓存回填、黑白名单、群授权、全员禁言等前置拦截。

## 权限与触发
- 触发方式: 被动触发
- 权限: 超级管理员

## 子功能目录
- `runtime-sync` 运行时同步: 在事件进入业务插件前回填用户、群、群成员缓存。
- `runtime-check` 运行时检查: 对忽略用户、超管、黑名单、群授权和全员禁言做统一拦截。

## 子功能详情
### `runtime-sync` 运行时同步
- 摘要: 在事件进入业务插件前回填用户、群、群成员缓存。
- 别名: 缓存回填, sync
- 指令: 被动触发
- Demo: hook-processor-runtime-sync.png
#### 说明
这个阶段会在每个事件到达业务 matcher 前，尝试同步用户昵称、群名、群名片和角色等缓存。
#### 前置条件
收到一个带用户或群上下文的事件。
#### 完整流程
同步动作对用户透明。
```demo
SYSTEM: 收到一条群消息事件。
先执行用户/群/成员缓存同步，再进入后续插件。
```
#### 失败情况
若缓存依赖的 API 不可用，可能导致部分字段缺失，需要通过日志排查。

### `runtime-check` 运行时检查
- 摘要: 对忽略用户、超管、黑名单、群授权和全员禁言做统一拦截。
- 别名: 拦截链, check
- 指令: 被动触发
- Demo: hook-processor-runtime-check.png
#### 说明
这个阶段会根据当前用户、群和插件 metadata 统一决定是否放行事件。
#### 前置条件
事件已完成基础同步，并且目标插件没有显式设置 `no_check=True`。
#### 完整流程
按固定顺序检查用户忽略、超管放行、全局黑名单、群授权和群黑名单。
```demo
SYSTEM: 收到一条来自未授权群的消息。
runtime-check 判定群聊未授权，事件被提前忽略。
```
#### 失败情况
如果群缓存缺失且无法补齐，默认会阻止群事件继续进入业务插件。
