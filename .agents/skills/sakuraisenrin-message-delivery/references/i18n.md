# 用户文案与 i18n

此处规定机器人产品文案的接入方式；代码注释、开发文档和内部机器标识不需要伪装成机器人翻译键。

## 文案边界

以下都属于用户可见产品文案：成功/失败回复、权限提示、参数说明、等待/进度提示、通知、帮助包装、插件名称/描述、图片中的标题/标签/图例、转发摘要和 fallback。

- 不在业务代码中写裸文案、f-string 文案或“翻译片段 + 固定中文后缀”。
- 完整句子/条目进入词典，用命名占位符传动态值；译文允许自主调整语序。
- 命令/别名、协议字段、路径、source_kind 等机器标识可以是常量；对它们的解释仍需本地化。
- 用户输入、用户昵称、数据库词条、外部原文是业务数据，作为参数或安全消息段传递，不强制改写成翻译键。
- 内部异常/日志不要求 i18n；展示给用户时使用本地化、可理解的错误说明，避免直接转发 traceback 或敏感细节。
- README 是文档内容源，保留结构化命令资料；代码生成的标题、解释、错误包装和摘要必须本地化。新增用户文档还须在计划中说明正文的多语言呈现方案，不能把静态中文来源当成其他 locale 已有翻译。

## 词典与键

| 文件 | 职责 |
| --- | --- |
| src/locales/zh_cn.py | 默认完整词典；生成键的来源 |
| src/locales/lzh.py | 必须与默认词典键集合一致 |
| src/locales/x_meme.py | 允许缺省键，按现有运行时回退到 zh-CN |
| src/lib/i18n/keys.py | 自动生成的 MessageKey/ALL_MESSAGE_KEYS，不手工维护 |
| src/lib/i18n/catalog.py | 纯查表与参数格式化 |
| src/lib/i18n/delivery.py | 事件/群组语言解析及兼容投递 helper |
| src/lib/i18n/runtime.py | 兼容导出入口；新代码优先使用上面两个职责模块 |

键使用稳定的业务语义，如 `<plugin>.<feature>.<result>`；可复用 common 键，但不为了减少键数拼接语言片段。用参数表达姓名、数量、ID 和时间，不用用户输入动态构造翻译键。

## 新增文案流程

1. 先查已有键及占位符，确认是否能完整表达语义。
2. 在 zh_cn 和 lzh 添加同名键；x_meme 按产品需要补充。各语言已有译文的占位符集合一致。
3. 在已批准的写入阶段运行生成器，然后校验：

```bash
uv run python -m src.lib.i18n.generate_keys
uv run python -m src.lib.i18n.check
```

生成器会改 keys.py，属于 Python 改动，随后执行根规范的全局门禁。校验器验证键/占位符完整性，不检查所有业务代码是否仍有硬编码，仍需审查改动路径。

## 语言解析与输出

```python
from src.lib.i18n.catalog import tr
from src.lib.i18n.delivery import get_group_locale, resolve_locale

locale = await resolve_locale(get_group_locale(event))
text = tr(locale, "admin.i18n.show.effective", locale=locale)
```

这是已有键的调用示例。群组覆盖与全局默认交给现有 resolver；不要在事件回复中为了方便固定 `zh-CN`。无事件的通知明确传入目标群组或全局语言语境。

译文再交给 delivery.md 中的统一消息计划。多轮交互在状态中保持语言语境；不能每一步用不同的临时默认值。多语言输出缓存以实际渲染文本与上下文为准，不能只用同一个文案键跨 locale 复用结果。

## 名称、帮助和图片

插件的静态 metadata 可以以默认语言初始化 `name`/`description`，但应同时提供：

```python
"i18n": {
    "name_key": "plugin.self_unban.name",
    "description_key": "plugin.self_unban.description",
}
```

示例对应现有 self_unban；新插件先建立自己的键。仅在模块导入时调用 `tr("zh-CN", ...)` 不代表后续帮助展示已经支持语言切换。

图片 renderer 接收解析后的 locale 或已经本地化的展示数据。Pillow draw_text、图例、日期/数量说明等也不得硬编码产品文案。帮助渲染通过 DocsRenderContext 传递语言和权限，不在插件里复制渲染器。

## 验证

对文案改动验证：必备语言键齐全、占位符一致、群组/全局语言解析、可选语言回退；参数中的 CQ 文本仍按字面输出。交互、图片或帮助改动按实际路径补回归；纯键/标点调整可复用现有覆盖并说明依据。
